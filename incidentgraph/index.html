TRANSPARENT DETECTION

Rules you can inspect.

Three explainable correlation rules. No threat intelligence feeds or machine learning are used.

  1. Successful login after repeated failures

    Same source, account, and host; a success follows the configured failure count within the time window.

  2. One source tried multiple accounts

    Failed logins from one source reach the configured number of distinct accounts within the time window.

  3. Privilege change after suspicious login

    A successful privilege change on the same account and host follows the first rule within 30 minutes.

INPUT CONTRACT

Make your logs readable.

This version accepts a normalized schema. Convert vendor-specific logs to these columns before import.

timestamp
ISO 8601 with timezone, e.g. 2026-10-14T08:00:00Z
action
login, privilege_change, file_access, or session_end
user / source / host
Account, source address or name, destination host
outcome
success or failure
details
Optional description (up to 2,000 characters retained)

Invalid rows are reported before import. Valid records are ordered by timestamp. Each event retains its original record and input row number.

The sample is fictional. 203.0.113.42 is a documentation address. No network probes, IP reputation lookups, or external requests are performed.
